# Design brief

Convert the request into observable product behavior before styling.

## Required frame

1. **User and situation** — who arrives, what they already know, and what
   prevents progress.
2. **Primary outcome** — the one action or understanding the screen must make
   easiest.
3. **Priority order** — rank content and actions. Equal visual weight is not a
   neutral choice; it hides priority.
4. **Proof** — identify the evidence, status, preview, price, example, or trust
   signal needed before the primary action.
5. **Constraints** — platform, viewport, locale, content variability, existing
   components, accessibility, performance, and implementation boundaries.
6. **Non-goals** — name content or interaction that should not compete on this
   screen.

## Decision test

For every prominent element, answer:

- Which ranked user need does it serve?
- What would break if it were removed or de-emphasized?
- Is its prominence supported by product priority or only by visual novelty?

Block on missing facts only when different answers would materially change the
screen. Otherwise state the assumption and keep it reversible.
