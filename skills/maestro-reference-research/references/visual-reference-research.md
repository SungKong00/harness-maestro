# Visual reference research

Use this profile only when the selected Guide is `reference-selection`.

## Source plan

Record the exact screen, platform, user task, viewport or device state, planned
queries, source roles, and stop conditions in the v2 `source_plan`.

Start with one shipped-product direct example. Add an adjacent example or
counterexample only when it changes transfer fit. Foundation, token, or
standards authorities may constrain the decision but do not count as observed
shipped-product examples.

## Evidence profile

For every shipped-product example record:

- exact URL or checked artifact and access date;
- exact screen, state, viewport, and user task actually observed;
- the inspected visual or interaction evidence;
- the transferable decision and non-transferable context;
- freshness, limitations, and confidence;
- the claim IDs the example supports or conflicts with.

If an interaction, responsive view, loading, error, empty, focus, or permission
state was not observed, mark it unknown. Never infer it from a static desktop
image.

Use `direct-evidence`, `adjacent-comparator`, `counterexample`,
`foundation-constraint`, and `skeptic` source roles explicitly. A design that
is fashionable or frequently copied is not authoritative by popularity.

## Synthesis

State:

- adopted principles and why they transfer to this project;
- rejected patterns and why they do not transfer;
- concrete implementation and verification checklist candidates;
- material visual or interaction conflicts;
- unobserved states and what would resolve them;
- confidence and freshness.

Keep all of that decision content in the validated v2 packets and synthesis.
Keep raw image files and copied pages outside the normal Assignment context.
