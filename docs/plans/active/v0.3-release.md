# Harness Maestro v0.3 계획

## 현재 상태

구현 범위와 자동 검증은 완료했다. 아래 체크리스트만 이 릴리스의 활성 TODO다.
보류 기능 전체를 여기에서 반복하지 않고
[제외·보류 목록](../../governance/deferred-and-excluded.md)을 권위로 사용한다.

### 릴리스 전 필수

- [ ] 실제 Codex Host에서 Fast·Standard·Deep·Decision-first conformance를 실행하고
      최소 결과 artifact를 `release-evidence/host-conformance/0.3.0-codex.json`에
      기록한다.
- [ ] GitHub ruleset으로 `v*` 태그의 수정·삭제를 막는다.
- [ ] 검토된 변경을 커밋하고 `v0.3.0` 태그와 함께 원격에 푸시한다.
- [ ] tag-triggered release workflow가 만든 wheel·sdist·checksum을 확인한다.
- [ ] 발행된 태그의 clean checkout에서 CLI와 여덟 Skill을 연결하고
      `maestro doctor --host codex --strict`를 통과시킨다.

### 릴리스 후 Pilot

- [ ] 빈 저장소에서 Markdown 기본 초기화·멱등성을 실제 사용 흐름으로 확인한다.
- [ ] 기존 문서와 `AGENTS.md`가 있는 프로젝트에서 관리 블록 밖 보존을 확인한다.
- [ ] 두 프로젝트의 반복 차이만 Adapter 또는 Convention 후보로 분류하고,
      일회성 차이는 전역 하네스에 반영하지 않는다.
- [ ] 한 프로젝트에서 Expertise candidate → reviewed project pilot → route 선택 →
      RunReceipt 집계를 실제 Host 흐름으로 확인한다.

완료된 자동 검증은 체크박스로 중복 관리하지 않는다. CI, test와 release manifest가
그 상태의 기계 권위다.

## 목표

두 개 이상의 프로젝트에서 기존 파일을 보존하며 설치할 수 있고, 필요한 문서와 Lens만
선택하며, 개선 신호를 live 설정과 분리해 보고하는 범용 최소 하네스를 만든다.

## v0 범위

### Core

- 안전한 init 미리보기와 검토한 plan 적용
- stack·후보 명령의 정적 Adapter 탐지
- 상태, managed hash, Registry와 문서의 read-only doctor
- 활성 문서의 제한적 선택과 archive 기본 제외
- Fast/Standard/Deep 위험 기반 Lens·Executor route
- project/checkout namespace가 있는 JSONL의 read-only governance report
- project와 checkout을 자동 채우는 작업 종료 RunReceipt writer
- 읽기 전용 status와 기존 init 계약을 재사용하는 upgrade
- 기존 문서 매핑 또는 `project.md`·`architecture.md` draft 생성
- 현재 프로젝트의 검증된 Convention 한 건만 허용하는 self-improvement
- Markdown 기본값과 프로젝트 소유 custom document Adapter handoff
- portable model class와 Codex host model mapping 분리
- CLI runtime, Registry와 여덟 Skill의 content-addressed release identity
- 이전 v0.2.2 project fixture에서 현재 버전으로의 upgrade 검증
- tracked `.agents/skills`와 project allowlist를 사용하는 로컬 Expertise pilot 활성화

### Registry와 Skill

- Lens, Executor, Department, Adapter의 분리 schema와 validator
- 일반 작업의 한 진입점인 `$maestro`
- 명시적 관리 작업에만 쓰는 Adapter builder와 governance Skill
- 조건부 research gate에만 쓰는 내부 Reference Research Skill
- product-design·marketing·software-qa pilot Expertise Pack
- RED baseline과 frozen coexistence 평가를 요구하는 Expertise Builder
- 일반 사용 Skill의 실제 사용자 요청 forward test

### 문서

- 활성 문서 지도와 typed frontmatter
- 구조·생명주기·제외 범위의 단일 권위 문서
- 채택 결정을 설명하는 ADR
- 민감한 기존 조사·설계 원문을 제외한 날짜별 처리 기록

## 릴리스 게이트

v0는 다음 증거가 모두 있을 때만 설치 가능한 초기 릴리스로 본다.

1. `python3 -m compileall`과 표준 라이브러리 test suite 통과
2. 빈 저장소, 기존 `AGENTS.md`, stale/tampered plan, symlink 경계와 idempotency test
3. Registry 타입 혼합, 다수결, 무제한 반박을 막는 pressure test
4. archive 제외, 상대 링크, 중복 활성 ID와 state namespace test
5. 실제 build한 wheel과 sdist를 source resource 목록과 대조하고, 각각 빈 환경
   설치·CLI·init을 smoke test하며, source checkout의 Skill digest와 packaged
   release identity가 일치하는 package test
6. 각 Skill의 정적 validator 통과
7. 실제 사용자 표현의 요청으로 `$maestro` forward test 통과
8. [Codex host conformance](../../runbooks/codex-host-conformance.md)의
   Fast·Standard·Deep 시나리오를 실제 host에서 확인
9. 독립 reviewer가 완료 주장과 command artifact를 대조

검증되지 않은 항목은 완료로 표시하지 않는다. token 값이 없는 run은 비용 개선
근거로 사용하지 않는다.

## v0 이후 후보

- source style별 ResearchLaneCard를 실행·합성하는 runtime research wave
- runtime capability broker, cancel/retry와 workspace lease
- stack pack과 external snapshot Adapter
- architecture-first/implementation-first/sandwich 순서 Pilot
- logging·OpenAPI specialist 존재 가치 Pilot
- project pilot을 일반화해 Harness 후보 PR로 만드는 global promotion workflow

후보의 현재 판정과 도입 조건은
[제외·보류 목록](../../governance/deferred-and-excluded.md)을 따른다.

## 종료와 다음 계획

릴리스 게이트가 통과하면 이 계획을 `plans/completed/`로 옮기고 status를 `archived`로
바꾼다. 다음 milestone은 실제 Pilot 데이터에서 정하며, 아직 측정하지 않은 agent
수나 token 임계치를 미리 고정하지 않는다.
